# Custom behaviors

Three selectable groups use source under `src/behaviors/`: Windows keyboard, Dock & gestures (DockMinimizer), and App close behavior (QuitOnRed). Preferences offers independent feature switches and Start at login. Application installs signed native helper apps under the destination user's Applications directory and prepares one LaunchAgent per helper. No executable payload is copied from Bruce's account. Apple Command Line Tools are required to build them.

Windows keyboard maps left/right physical Ctrl to Command and physical Windows-logo to Control. Alt remains Option. Device identities come from the destination's live HID services. Matching existing host-specific maps are reused without applying a second swap. Conflicting maps are preserved and shown in the helper menu status. Runtime maps owned by this helper are cleared when it stops, only if they still match its applied map; reboot clears runtime HID mappings too. The login helper reapplies to newly connected keyboards. It does not copy Bruce's vendor/product IDs or change Caps Lock. Use native Keyboard settings for device-specific exceptions.

DockMinimizer offers active-app Dock click to minimize, Finder minimize/restore, Alt+Tab/Alt+Shift+Tab through the native switcher, short uncombined Control tap to open the macOS 27 Apps launcher, and clearing launcher search when reopened. With Windows keyboard mapping, the physical Windows-logo key produces that Control tap. Modified clicks and ordinary Option shortcuts retain their normal behavior. Search-reset work cancels as soon as the user starts input. Older macOS versions cannot select the macOS 27 launcher group.

QuitOnRed independently enables red-button app quit, Edge last-tab quit, and Terminal last-tab quit. Shift-click red closes only that window. Finder and protected system apps keep normal behavior. Quit requests are ordinary termination requests; save/cancel dialogs are respected. The final-window monitor first observes a normal window, then waits for every window to close, including minimized windows/dialogs, and rechecks before requesting quit. It does not quit an app merely because it launched without a window. Terminal profiles close the window after shell exit; QuitOnRed then requests Terminal quit when no windows remain.

Review discloses source builds, saved preferences and login-file changes. Helpers build and self-check in a private run stage before configuration writes. An existing or edited helper needs the separate recommended repair approval; the entire prior app is moved to that run's backups. A recognized legacy LaunchAgent is reused so two login jobs are not installed. Helper sources, executable, Info.plist, source stamp, login file and preference observations participate in freshness checks.

After Apply, open the installed helper from `~/Applications`, or sign in again if Start at login is enabled. Existing instances are not duplicated. After rebuilding an already-running helper, quit its old instance through its menu before starting the new build. Window helpers require Accessibility approval; macOS may require removing and re-adding a rebuilt app. The app cannot grant Accessibility or Background Activity approvals. Utilities opens the relevant System Settings page with guidance. Disabling login does not terminate an already-running helper; use its menu to stop it. Saved-state Verify checks installed/configured state, not actual input interception or macOS permission approval.

Recovery: stop the affected helper through its menu first. Helper replacement records use `helper-backup`, `helper-installed` and `helper-staged` in the run's events.txt. Restore the whole recorded app backup only after checking later changes. Login files use ordinary numbered file backups. Restore helper preference keys through recover-preferences as for other typed preferences. Accessibility grants may need to be selected again after restoration. Whole-run rollback is not automatic.

Tests compile all sources, execute only their --self-test branches, and install into temporary homes with injected preference stores. They never start background helpers, intercept input, grant permissions, quit Edge/Terminal, or edit the source Mac's modifier map. End-to-end gesture behavior across OS/hardware combinations still requires explicit interactive use after permission approval.

Sources: [Apple HID remapping](https://developer.apple.com/library/archive/technotes/tn2450/_index.html), [Login & background settings](https://support.apple.com/en-hk/guide/mac-help/mtusr003/27/mac/27), and [upstream DockMinimizer](https://github.com/Stoyanruh/DockMinimizer). See src/behaviors/NOTICE.md for attribution.


## Wallpaper and screen protection

DockMinimizer and QuitOnRed exclude wallpaper/screen-saver renderers, login/security components and background system services from window/quit actions. Global actions pause during screen saving, display sleep, lock or an inactive console session. Deferred actions are cancelled and rechecked before execution. Ordinary continuously running wallpaper agents do not pause normal desktop use. Real screen-saver/lock transitions remain an interactive check; automated cases use metadata/state fixtures without activating a saver or locking the Mac.

Appearance is Keep current by default. An explicit Light/Dark choice can change Automatic wallpaper appearance, as described in [Apple's Wallpaper settings](https://support.apple.com/en-am/guide/mac-help/mchlp1103/mac). The safety fix never rewrites the wallpaper database, deletes its assets or restarts wallpaper services.

Mac Tweak itself uses a regular app identity, so Dock minimization and the other normal window behaviors also apply to its windows. Source launches use a cached macOS app host; the release runs the same JXA UI inside its native launcher process. No renderer/session exclusions or helper privacy approvals are weakened.
